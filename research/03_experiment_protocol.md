# Data Agent 部门级语义增益实验

更新时间：2026-08-03

## 1. 实验问题

实验不是判断“知识图谱是否漂亮”，而是回答：

1. 资产映射和 SQL 事实是否提升报表、表、字段和 SQL 召回？
2. 报表局部语义是否提升别名理解和指标口径选择？
3. 部门内语义对齐是否提升跨报表迁移，同时不会扩大错误合并？

## 2. 数据集构造

模拟数据保留用户四类源文件结构，并故意包含：

- 1～5段路径、空片段、前后空格和名称漂移；
- 系统组件名与有业务含义的组件名；
- 重复 SQL、同组件多 SQL、一个 SQL 多表；
- 数据集跨报表复用；
- 无语义别名 `LONG_COL_0`、`c27`；
- 同义表达：销售额/销额、客户ID/客户编号/客商编码；
- 同名不同口径：含税销售额/不含税销售额、不同订单状态；
- 字段血缘缺失、错误字段、孤立报表和未登记物理表；
- 公共日期/组织表，验证它们不会制造巨型错误候选簇；
- 部门外设备/传感器报表，验证部门边界是否隔离噪声。

评测 fixture 另含少量受控行数据，只用于 SQL 执行评分，不作为语义抽取输入。

## 3. 对照组

| 组 | 给 Agent 的上下文 | 目的 |
|---|---|---|
| A | 物理表和字段注释 | 空白 Agent 的合理基线 |
| B | A + 报表/组件/数据集/SQL 事实 | 测资产映射本身的贡献 |
| C | B + 报表局部 claim | 测局部语义发现的贡献 |
| D | C + 部门候选对齐结果 | 测跨报表部门语义的增量贡献 |

## 4. 任务类型

- 资产定位：返回正确报表、组件、数据集、表和字段；
- 指标理解：选择正确表达式、聚合、过滤、粒度和单位；
- 差异解释：解释两个报表同名指标为何不同；
- SQL 生成：生成可解析、可执行且结果等价的 SQL；
- 影响分析：定位某字段变化影响的报表和局部概念；
- 拒答/澄清：证据不足或口径冲突时不得自行合并。

## 5. 自动评分

- Asset Recall@K、MRR；
- Table/Field/Report/Component exact match；
- 正确指标实现要素覆盖率；
- SQL parse rate、execution accuracy、结果等价率；
- 候选压缩率：进入 LLM 的候选对 / 理论全量候选对；
- 冲突保留率和错误合并率；
- 证据引用合法率；
- 单问题 token、耗时和 API 调用次数。

不使用“让同一个大模型给自己的答案打0～100分”作为主指标。解释文本只做抽样人工
检查；资产、字段、口径要素和 SQL 尽量由程序对照 gold 判断。

## 6. 第一轮通过条件

第一轮不预设一定有效，最低通过条件是：

1. C 相比 B 在别名/口径问题上有可重复提升；
2. D 相比 C 在跨报表问题上有提升，且错误合并不增加；
3. 所有被使用的语义都能回到报表、组件、SQL、表或字段证据；
4. 总候选数相对全量两两比较至少下降一个数量级；
5. 删除语义层后，评测能够明确显示哪些问题退化，而不是只展示图节点数量。
