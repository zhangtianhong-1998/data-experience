# 复现手册：从新 clone 到逐套运行

## 说明

下面是可读的逐套命令，不要求六个重量级服务同时运行。DataHub 和 OpenMetadata 都使用 3306/9200，因此必须串行启动；本次实测也正是这样完成的。

所有命令从仓库根目录执行：

```bash
export DEMO_ROOT="$(pwd)"
```

需要：

- macOS/Linux
- Docker Desktop，建议至少 8 GB 可用内存
- `uv`
- Python 3.11 和 3.12（由 uv 下载也可）
- 可访问 Docker registry/GitHub/PyPI
- 仅路线 3 需要相邻 `../data-ex/.env`，键名为 `THIRD_PARTY_API_KEY`、`THIRD_PARTY_BASE_URL`、`THIRD_PARTY_MODEL`

不要把 `.env` 拷进本仓库。

## 0. 公共工具和数据

```bash
uv venv --python 3.12 runtime/.venv-tools
uv pip install --python runtime/.venv-tools/bin/python \
  -r runtime/requirements-tools.txt

cd demos/common
"$DEMO_ROOT/runtime/.venv-tools/bin/python" build_and_verify.py
cd "$DEMO_ROOT"
```

期望：`device_orders=16`、`product_master=3`、`sales_orders=3`，baseline verification passed。

## 1. MetricFlow

安装：

```bash
uv venv --python 3.12 runtime/metricflow-venv
uv pip install --python runtime/metricflow-venv/bin/python \
  'dbt-metricflow[dbt-duckdb]==0.13.0'
```

运行：

```bash
cd demos/route1/metricflow/device_project
export MF_DUCKDB_PATH="$DEMO_ROOT/demos/common/demo.duckdb"

"$DEMO_ROOT/runtime/metricflow-venv/bin/dbt" clean --profiles-dir .
"$DEMO_ROOT/runtime/metricflow-venv/bin/dbt" build --profiles-dir .
"$DEMO_ROOT/runtime/metricflow-venv/bin/mf" validate-configs

"$DEMO_ROOT/runtime/metricflow-venv/bin/mf" query \
  --metrics device_order_amount,device_profit_amount \
  --group-by device_order__product_l1 \
  --where "{{ Dimension('device_order__org_code') }} = 'ORG_1001'" \
  --start-time 2026-01-01 \
  --end-time 2026-06-30 \
  --order device_order__product_l1 \
  --csv results/org1001_h1_by_product.csv \
  --explain --show-dataflow-plan

cd "$DEMO_ROOT"
runtime/.venv-tools/bin/python demos/route1/metricflow/verify_result.py
```

## 2. Cube

```bash
cd demos/route1/cube
docker compose down -v --remove-orphans
docker compose pull
docker compose up -d
"$DEMO_ROOT/runtime/.venv-tools/bin/python" run_query.py
docker compose down
cd "$DEMO_ROOT"
```

`run_query.py` 会等待 `/meta` ready，再调用 `/sql` 与 `/load`，写出三个 result JSON。

## 3. WrenAI

安装：

```bash
uv venv --python 3.12 runtime/wren-venv
uv pip install --python runtime/wren-venv/bin/python 'wrenai[mcp]==0.13.2'
uv pip install --python runtime/wren-venv/bin/python --reinstall \
  'mcp[cli]>=1.19,<2'
```

运行 CLI：

```bash
cd demos/route1/wrenai/device_project
"$DEMO_ROOT/runtime/wren-venv/bin/wren" context validate --strict
"$DEMO_ROOT/runtime/wren-venv/bin/wren" context build
"$DEMO_ROOT/runtime/wren-venv/bin/wren" cube query \
  --from cube_query.json --connection-file connection.json --output json
cd "$DEMO_ROOT"
```

运行 MCP 时，在第一个终端：

```bash
cd "$DEMO_ROOT/demos/route1/wrenai/device_project"
"$DEMO_ROOT/runtime/wren-venv/bin/wren" serve mcp \
  --transport http --host 127.0.0.1 --port 8081
```

在第二个终端调用 [`invoke_mcp.py`](../demos/route1/wrenai/invoke_mcp.py)。如调整端口，请同步客户端 URL。运行完停止 MCP 进程。

### 3.1 真实 LLM 生成 Cube/Wren DSL

先完成上面的 Cube Meta 保存和 Wren `context build`。然后从仓库根目录运行：

```bash
runtime/.venv-tools/bin/python demos/route1/nl_to_dsl/run_experiment.py
```

脚本只在运行时读取相邻 `data-ex/.env` 的 `THIRD_PARTY_API_KEY`、`THIRD_PARTY_BASE_URL` 和 `THIRD_PARTY_MODEL`，不会把 key 或 base URL 写入结果。

执行通过校验的 DSL：

```bash
cd demos/route1/cube
docker compose up -d
cd ../../..
runtime/.venv-tools/bin/python demos/route1/nl_to_dsl/execute_generated.py
cd demos/route1/cube
docker compose down -v --remove-orphans
```

预期 `llm_summary.json` 为 10/10，`execution_summary.json` 为 4/4。历史两轮失败是研究证据，不需要在普通复跑时重造。

## 4. DataHub

安装 CLI 与官方 MCP server：

```bash
uv venv --python 3.12 lab/.venv
uv pip install --python lab/.venv/bin/python \
  'acryl-datahub[sqlalchemy]==1.6.0' fastmcp

git clone https://github.com/acryldata/mcp-server-datahub.git \
  lab/vendor/mcp-server-datahub
uv pip install --python lab/.venv/bin/python \
  -e lab/vendor/mcp-server-datahub
```

洁净启动与采集：

```bash
lab/.venv/bin/datahub docker nuke

cd demos/route2/datahub
"$DEMO_ROOT/runtime/.venv-tools/bin/python" build_sqlite.py

cd "$DEMO_ROOT"
lab/.venv/bin/datahub docker quickstart

cd demos/route2/datahub
export DEMO_SQLITE_PATH="$DEMO_ROOT/demos/route2/datahub/input/datahub_demo.db"
"$DEMO_ROOT/lab/.venv/bin/datahub" ingest -c ingest_sqlite.yml
"$DEMO_ROOT/lab/.venv/bin/python" enrich.py

export DATAHUB_QUERY_FILE="$DEMO_ROOT/demos/route2/datahub/input/query_history.jsonl"
"$DEMO_ROOT/lab/.venv/bin/datahub" ingest -c ingest_queries.yml
```

启动 MCP：

```bash
cd "$DEMO_ROOT"
DATAHUB_GMS_URL=http://localhost:8080 \
DATAHUB_MCP_DOCUMENT_TOOLS_DISABLED=true \
lab/.venv/bin/mcp-server-datahub --transport http
```

另一个终端：

```bash
cd "$DEMO_ROOT/demos/route2/datahub"
"$DEMO_ROOT/lab/.venv/bin/python" invoke_mcp.py
"$DEMO_ROOT/lab/.venv/bin/python" verify.py
```

刚写入 query history 后若 `total=0`，等待约 20 秒让 OpenSearch 刷新后重试。结束：

```bash
cd "$DEMO_ROOT"
lab/.venv/bin/datahub docker quickstart --stop
```

## 5. OpenMetadata

先确保 DataHub 已停止。安装 exact-version ingestion client：

```bash
uv venv --python 3.11 runtime/openmetadata-venv
uv pip install --python runtime/openmetadata-venv/bin/python \
  'openmetadata-ingestion[mysql]==1.13.0.0'
```

洁净启动：

```bash
docker compose -p data-experience-openmetadata \
  -f demos/route2/openmetadata/official/docker-compose.yml \
  -f demos/route2/openmetadata/compose.override.yml \
  down -v --remove-orphans

docker compose -p data-experience-openmetadata \
  -f demos/route2/openmetadata/official/docker-compose.yml \
  -f demos/route2/openmetadata/compose.override.yml \
  up -d mysql elasticsearch execute-migrate-all openmetadata-server
```

等待 `openmetadata_server` healthy，然后：

```bash
cd demos/route2/openmetadata
"$DEMO_ROOT/runtime/.venv-tools/bin/python" bootstrap_source.py
"$DEMO_ROOT/runtime/.venv-tools/bin/python" get_demo_token.py
"$DEMO_ROOT/runtime/.venv-tools/bin/python" run_local_ingestion.py
"$DEMO_ROOT/runtime/openmetadata-venv/bin/python" enrich_and_read_sdk.py
"$DEMO_ROOT/lab/.venv/bin/python" invoke_mcp.py
"$DEMO_ROOT/runtime/.venv-tools/bin/python" verify.py
cd "$DEMO_ROOT"
```

本地 JWT 保存在 `runtime/openmetadata-1.13.0/`，已被 gitignore。停止：

```bash
docker compose -p data-experience-openmetadata \
  -f demos/route2/openmetadata/official/docker-compose.yml \
  -f demos/route2/openmetadata/compose.override.yml stop
```
